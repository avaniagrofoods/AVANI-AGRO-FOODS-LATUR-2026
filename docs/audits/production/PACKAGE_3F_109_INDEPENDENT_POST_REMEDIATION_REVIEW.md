## 3. VERIFICATION OF MIDDLEWARE & AUTHENTICATION

### 3.1 Session Format & Cookie Agreement (`FIXED_AND_TESTED`)
- In `api/_lib/auth.js:513`, `createServerSession` creates 64-hexadecimal session identifiers via `crypto.randomBytes(32).toString('hex')` signed as `<sessionId>.<hmacSignature>`.
- In `middleware.js:11-30`, `verifyCookieFormat` accepts `/^[a-f0-9]{64}$/i` as well as legacy prefixed identifiers, with signature length $\ge 16$.
- Passing legitimate 64-hex session cookies to `middleware(request)` allows the request to pass through without Edge rejection (verified by `T-108-01`).

### 3.2 Edge Defense in Depth & API Authority (`FIXED_AND_TESTED`)
- Edge middleware performs only coarse syntactic format filtering.
- Downstream serverless handlers (`api/verify-gate.js`, `api/admin-quotations.js`, `api/importers.js`, etc.) perform authoritative cryptographic verification via `verifyServerSession(req, role)`.
- Authoritative checks verify:
  1. HMAC-SHA256 signature using `SESSION_SECRET` (timing-safe).
  2. Timestamp expiry against `SESSION_TTL_SECONDS`.
  3. Server-side session record lookup in Upstash Redis KV (`session:<role>:<sessionId>`).
  4. Revocation state check. If session was revoked via logout, access is denied with 401 `SESSION_REVOKED`.
  5. KV failure handling: If KV is configured or required (`REQUIRE_DISTRIBUTED_KV=1`) and fails, the check returns 503 `SESSION_BACKEND_UNAVAILABLE` and strictly **never falls back to signature-only validation**.

### 3.3 Elimination of Master Password Bearer Authentication (`FIXED_AND_TESTED`)
- `middleware.js:34-42` previously allowed raw master passwords in `Authorization: Bearer <password>`. This logic has been completely removed.
- In `middleware.js:53-63`, Bearer tokens are permitted to pass through to downstream handlers only if they match explicit machine secrets:
  ```javascript
  const cronSecret = (process.env.CRON_SECRET || '').trim();
  const adminApiKey = (process.env.ADMIN_API_KEY || '').trim();
  if ((cronSecret && token === cronSecret) || (adminApiKey && token === adminApiKey)) {
    return;
  }
  ```
- Submitting `Authorization: Bearer <MASTER_GATE_PASSWORD>` returns HTTP 401 `Unauthorized admin access` at the Edge (verified by `T-108-06`).

### 4.5 Webhook Persistence & Quotation Lifecycle Audit (`NOT_FIXED` / `BLOCKED`)

A complete architectural trace of the quotation delivery lifecycle reveals an irreconcilable disconnect between the serverless webhook receiver and quotation persistence:

```
[Admin Browser (SPA)]
       │
       ├─ 1. Admin creates quotation ──────► Saved in browser localStorage ('avani_quotations')
       │                                     Optional export to Google Sheets via Apps Script webhook
       │
       ├─ 2. Admin clicks 'Send to Buyer' ─► Calls POST /api/admin-quotations?action=send-buyer
       │                                     Dispatches email via Resend API
       │                                     Returns { success: true, messageId: 'msg_123', quotation }
       │
       └─ 3. Browser saves messageId ──────► Updated in browser localStorage ('avani_quotations')
                                             (NO record created in Supabase database!)

[Resend Webhook Server]
       │
       └─ 4. Email Delivered ──────────────► POST /api/admin-quotations?action=delivery-webhook
                                             Headers: svix-id, svix-timestamp, svix-signature
                                             Body: { type: 'email.delivered', data: { email_id: 'msg_123' } }
                                                   │
                                                   ▼
                                     [Vercel Serverless Function]
                                     - Edge Middleware passes through (exemption verified)
                                     - Stream read into req.rawBody
                                     - Svix HMAC signature verified against RESEND_WEBHOOK_SECRET
                                     - CANNOT FIND QUOTATION!
                                       - Serverless function has no access to browser localStorage.
                                       - Serverless function has no quotation database in Supabase.
                                       - No table named 'public.quotations' exists.
                                     - Result: Webhook returns HTTP 200 acknowledgment,
                                       but ZERO quotation records are updated in storage!
```

**Conclusion:** Webhook delivery tracking in production is **functionally inoperative** because the system lacks a server-authoritative quotation repository. When the administrator visits `/admin/quotations`, the quotation remains permanently in `SENT_TO_BUYER` status and will never reflect `DELIVERED`.

### 4.6 Webhook Replay Deduplication / Idempotency (`PARTIALLY_FIXED`)
- `api/_lib/quotationModel.js:524` defines:
  ```javascript
  const seenWebhookEventIds = new Set();
  ```
- **Architectural Vulnerability:** In a serverless architecture (Vercel), lambdas are stateless and ephemeral. An in-memory `Set` exists only within a single container execution context. When concurrent webhook retries hit different serverless instances, or when a lambda cold-starts, `seenWebhookEventIds` is empty. True serverless idempotency requires atomic deduplication in Upstash Redis KV (`SET nx ex 86400`).
