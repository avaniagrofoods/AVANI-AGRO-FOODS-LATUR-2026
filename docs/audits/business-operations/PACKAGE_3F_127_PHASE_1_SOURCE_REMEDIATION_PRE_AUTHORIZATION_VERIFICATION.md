## 1. EXECUTIVE SUMMARY

This package delivers an independent adversarial, strictly read-only verification of the proposed **Phase 1 source-code correction** affecting inquiry-to-quotation relationship integrity in `api/_lib/supabaseClient.js`.

Acting as Senior Independent Application Security Auditor, Supabase/PostgreSQL Database Integrity Specialist, Node.js Backend Architect, API Security Reviewer, and Adversarial Software Verification Engineer, the codebase, request boundaries, migration files, and error pathways were subjected to rigorous security and data-integrity analysis.

### Primary Audit Findings:
1. **The Root Cause Defect is Proven:** In `api/_lib/supabaseClient.js:239`, the condition `!rawInquiryId.startsWith('AAF-INQ-2026-')` actively rejects every legitimate inquiry ID generated by `api/save-lead.js:162`. This forces `safeInquiryId = null` at insert time, severing the relational link between buyer enquiries and quotations across 100% of newly submitted RFQs.
2. **Untrusted Client ID Override Vulnerability Discovered:** In `api/save-lead.js:162`, the logic reads `const inquiryId = body.inquiryId || 'AAF-INQ-2026-' + randSuffix;`. Because `/api/save-lead` is an unauthenticated public endpoint, an external attacker can submit an arbitrary `body.inquiryId`. Because `saveLeadToSupabase` uses `Prefer: resolution=merge-duplicates`, supplying an existing buyer's `inquiryId` causes an unauthorized UPSERT overwrite in `public.leads`!
3. **One-File vs Two-File Correction:** Correcting `api/_lib/supabaseClient.js` alone resolves the foreign-key stripping bug, but leaves the public `body.inquiryId` override open. Phase 1 must include a hardening safeguard on `api/save-lead.js:162` to enforce that public web enquiries generate IDs strictly on the server.
4. **Zero Database Migrations Required for Phase 1:** `supabase/migrations/20261110_quotations_table.sql:12` already establishes `inquiry_id VARCHAR(50) REFERENCES public.leads(inquiry_id) ON DELETE SET NULL`. Phase 1 requires **0 SQL migrations**.
5. **Phase 1 Authorization Recommendation:** **`READY_WITH_CONDITIONS`**. The source remediation is viable and minimal, but authorization must be conditioned on sealing the public `body.inquiryId` client-override vector.

## 7. INVESTIGATION D — POSTGRESQL ERROR HANDLING

### 7.1 PostgREST & Constraint Error Trapping
In `api/_lib/supabaseClient.js:277`:
- If an invalid or nonexistent `inquiry_id` is sent to PostgREST, PostgreSQL raises error `23503 foreign_key_violation`.
- PostgREST converts this to HTTP 409 Conflict with body:
  `{"code":"23503","message":"insert or update on table \"quotations\" violates foreign key constraint \"quotations_inquiry_id_fkey\""}`.
- In `supabaseFetch` (`api/_lib/supabaseClient.js:95`), status 409 is recognized as a non-retryable 4xx client error (`res.status < 500`). The retry loop aborts cleanly without exponential backoff spam.
- `saveQuotationToSupabase` returns `{ persisted: false, status: 'FAILED', error: ... }`.

### 7.2 Safety Assessment:
- **Foreign-key violations are NOT swallowed into silent NULLs by PostgreSQL.** PostgreSQL rejects the row outright.
- In `api/save-lead.js:328`, if `saveQuotationToSupabase` fails with 23503, the lead record remains preserved in `public.leads`, and `save-lead.js` returns HTTP 200 with `integrations.quotePersistence: 'FAILED'`, alerting the sales desk while preventing data loss of the buyer's inquiry.

## 8. INVESTIGATION E — MINIMUM SAFE CORRECTION

### 8.1 Comparison: Current vs Proposed Minimal Safe Correction

#### BEFORE (`api/_lib/supabaseClient.js:237-240`):
```javascript
  // Pure quotations without genuine pre-existing lead set inquiry_id to NULL (Owner Decision 1)
  const rawInquiryId = quoteRecord.inquiryId || quoteRecord.leadId || null;

```

#### AFTER (Minimal Safe Correction):
```javascript
  // 1. Resolve raw candidate inquiry ID
  const candidateId = typeof quoteRecord.inquiryId === 'string' && quoteRecord.inquiryId.trim()
    ? quoteRecord.inquiryId.trim()
    : (typeof quoteRecord.leadId === 'string' && quoteRecord.leadId.trim() ? quoteRecord.leadId.trim() : null);

  // 2. Strict format validation: accept canonical AAF-INQ-YYYY-XXXXXX or legacy AAF-L-YYYY-XXXX (max 50 chars)
  let safeInquiryId = null;
  if (candidateId) {
    if (candidateId.length <= 50 && /^AAF-(INQ|L)-\d{4}-[A-Za-z0-9-]+$/.test(candidateId)) {
      safeInquiryId = candidateId;
    } else {
      console.warn(`[SupabaseClient] Malformed inquiry_id rejected: "${candidateId}". Persisting quotation with inquiry_id = null.`);
      safeInquiryId = existingDelivery?.inquiry_id || null;
    }
  } else {
    // Standalone quotations without lead reference persist inquiry_id = null (permitted by foreign key)
    safeInquiryId = existingDelivery?.inquiry_id || null;
  }
```
